# BLE 저울 연동 — 검토 결과

작성일: 2026-08-19 / Phase 4
결론: **지금은 구현하지 않습니다.** 구조만 막아두지 않고 남겨둡니다.

---

## 무엇을 하려던 것인가

기획서 6.3절에서 이렇게 적었습니다.

> Acaia · Timemore Black Mirror · Bookoo 같은 BLE 저울은 Web Bluetooth API로 실시간 무게를 읽을 수 있습니다.
> 이게 되면 P4 가이드가 시간 기준이 아니라 **무게 기준 자동 진행**으로 바뀌어 정확도가 크게 올라갑니다.

지금 추출 가이드는 **시간 기준**입니다. 레시피가 "0:45에 120g까지"라고 하면 타이머가 0:45에 다음 단계로 넘어갑니다.
실제로 사람은 목표 무게를 채우느라 늦어지므로, 저울이 무게를 직접 읽으면 "120g에 도달하면 다음 단계"로 바꿀 수 있습니다.

---

## 검토 1 — 브라우저 지원

가장 결정적인 문제입니다.

| 브라우저 | 지원 |
|---|---|
| Chrome (데스크톱 · Android) | 지원 |
| Edge · Opera · Samsung Internet | 지원 |
| **Safari (iOS · iPadOS · macOS)** | **미지원** |
| **Firefox** | **미지원** (2015년부터 명시적 거부, 프라이버시 사유) |

**이 프로젝트는 모바일 우선입니다.** 그리고 아이폰 사용자는 Safari 외에 선택지가 없습니다.
iOS의 Chrome도 내부적으로는 WebKit이라 Web Bluetooth를 쓸 수 없습니다.

전 세계 브라우저 지원율은 2026년 4월 기준 76% 수준이지만,
**"주방에서 폰으로 커피를 내리는 사람"** 으로 좁히면 실제 사용 가능 비율은 훨씬 낮습니다.

---

## 검토 2 — 저울마다 프로토콜이 다릅니다

BLE 표준에는 "저울" 프로파일이 없습니다. 제조사마다 독자 GATT 서비스를 씁니다.

- Acaia (Pearl · Lunar) — 자체 프로토콜, 하트비트 패킷을 주기적으로 보내야 연결이 유지됨
- Timemore Black Mirror — 별도 프로토콜
- Bookoo · Felicita · Difluid — 각자 다름

즉 **저울 한 종을 지원하는 것은 그 저울 하나를 위한 코드를 쓰는 일**입니다.
커뮤니티가 리버스 엔지니어링한 명세가 있지만 펌웨어 업데이트로 깨질 수 있습니다.

---

## 검토 3 — 테스트할 수 없습니다

제가 BLE 저울을 갖고 있지 않습니다.
연결·재연결·패킷 파싱·연결 끊김 처리를 **실기기 없이 작성하면 동작 여부를 확인할 방법이 없습니다.**

추출 가이드는 이 앱에서 가장 실패 비용이 큰 화면입니다.
3분짜리 추출 도중에 연결이 끊겨 타이머가 멈추면 그 잔은 버리게 됩니다.
검증 못 한 코드를 그 경로에 넣는 것은 맞지 않습니다.

---

## 결론과 조건

**지금은 만들지 않습니다.** 다음 조건이 갖춰지면 재검토합니다.

- [ ] BLE 저울을 실제로 보유 (Timemore Black Mirror 또는 Bookoo가 국내 접근성이 나음)
- [ ] 주 사용 기기가 Android이거나, iOS는 지원하지 않는다고 명시할 수 있음
- [ ] 지원 저울을 1종으로 한정할 수 있음

---

## 만든다면 이렇게

지금 구조가 이 방향을 막고 있지 않다는 점을 확인해 뒀습니다.

**1. 점진적 향상으로만**

```js
// 저울이 없으면 지금과 똑같이 동작해야 합니다.
// 저울 연결은 '있으면 더 좋은' 기능이지 전제 조건이 아닙니다.
if ('bluetooth' in navigator) { /* 연결 버튼 노출 */ }
```

**2. `BrewSession`에 무게 소스를 주입**

현재 `BrewSession`은 `Date.now()`만 봅니다.
무게 기준 진행을 넣으려면 다음 단계 조건을 **시간 OR 무게** 중 먼저 오는 쪽으로 바꾸면 됩니다.

```
현재:  t >= next.startS                    → 다음 단계
확장:  t >= next.startS || w >= next.targetG → 다음 단계
```

`BrewPlan.at(plan, t)`가 순수 함수라 `at(plan, t, weight)`로 인자만 늘리면 되고,
기존 테스트 44건이 그대로 회귀 테스트 역할을 합니다.

**3. 시간 기준을 지우지 않습니다**

저울이 연결돼 있어도 시간 기준은 폴백으로 남깁니다.
연결이 끊기면 조용히 시간 기준으로 되돌아가고, 화면에 그 사실을 표시합니다.

**4. 로그에 무게 실측을 추가**

`BrewLog.actual.marks`에 이미 단계 전환 시각을 기록합니다.
여기에 `at_g`를 추가하면 "목표 120g에서 실제로 몇 g에 넘어갔는가"가 남습니다.
이건 저울 없이도 손으로 입력할 수 있으므로, **저울 연동보다 먼저 해볼 만합니다.**

---

## 대신 지금 한 것

Phase 4에서는 저울 대신 **TDS 미터 입력**을 넣었습니다.

- 테이스팅 입력에 TDS %와 추출량(g)을 선택 항목으로 추가
- 추출량을 안 재면 `물량 − 도징 × 2`로 추정
- 추출 수율을 계산해 18~22% 참고 구간과 함께 표시
- 분석 화면에서 수율 추이를 기준선과 함께 그림

TDS 미터도 없으면 비워두면 됩니다. 나머지 기능은 그대로 동작합니다.
**측정 장비가 있으면 더 정밀해지되, 없어도 막히지 않는다** — 저울 연동도 같은 원칙으로 갈 것입니다.
