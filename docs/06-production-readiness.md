## 1. 추출 중에 깨지는 것 — 최우선

여기가 진짜 문제입니다. 나머지는 불편이지만 이건 **내리던 커피를 망칩니다.**

### 1.1 뒤로가기 = 앱 종료

`pushState`가 한 번도 없습니다. 화면 전환이 전부 자바스크립트 상태 변수로만 일어납니다.

그래서 이렇게 됩니다.

- 안드로이드 하드웨어 백버튼 → 브라우저가 이전 **사이트**로 나감
- iOS 좌측 엣지 스와이프 → 마찬가지
- 3분짜리 추출 2분 30초 지점에서 이게 일어나면 **타이머가 통째로 사라집니다**

젖은 손으로 폰을 잡다가 엣지 스와이프가 걸리는 건 드문 일이 아닙니다.

**고칠 방향**

화면마다 `history.pushState`를 쌓고 `popstate`에서 되돌립니다. 추출 화면에서는
한 단계 더 필요합니다 — 진행 중일 때 뒤로가기가 들어오면 바로 나가지 말고
"추출을 중단할까요?" 확인을 띄웁니다. `beforeunload`로 탭 닫기도 같이 막습니다.

작업량은 중간입니다. 화면이 9개뿐이고 상태가 이미 `page` 하나로 모여 있어서
매핑이 단순합니다.

> **✓ 완료** — `assets/router.js`로 분리했습니다. DOM을 만지지 않는 순수 변환이라
> 테스트가 쉽습니다.
>
> **pushState가 아니라 해시(`#/`)를 썼습니다.** 이 사이트는 GitHub Pages의
> 하위 경로에 있습니다. pushState로 `/special-coffee-wiki/brew/xxx` 같은 주소를
> 만들면 그 상태에서 새로고침했을 때 서버가 그런 파일을 찾다가 404를 냅니다.
> 정적 호스팅이라 리라이트 규칙을 넣을 수 없습니다. 해시는 서버로 전송되지
> 않아 어떤 주소든 index.html이 뜨고 새로고침도 깨지지 않습니다.
>
> ```
> #/                       홈
> #/brew/<id>              추출 준비   ← 공유 가능한 링크
> #/brew/<id>/timer        타이머
> #/recipe/<id>            레시피 상세
> #/flavor/<노드>          향미 드릴다운
> #/bean/<id>  #/wiki/<id>  #/logs/<id>
> ```
>
> **URL에 넣을 것과 넣지 않을 것을 갈랐습니다.** 화면 이동은 넣고, 필터와
> 다중 선택은 넣지 않습니다. 칩 하나 누를 때마다 히스토리가 쌓이면 뒤로가기를
> 열두 번 눌러야 이전 화면으로 갑니다. 그건 라우팅이 없는 것보다 나쁩니다.
> 예외는 향미 드릴다운입니다 — 그건 필터가 아니라 이동이라, 뒤로가기가
> "위로 올라가기"가 되는 게 자연스럽습니다.
>
> 추출 중 이탈은 두 겹으로 막습니다. 뒤로가기는 `hashchange`에서 확인을 받고
> 취소하면 주소를 되돌립니다. 탭 닫기와 새로고침은 `beforeunload`로 막습니다.
> 뒤로가기만 막으면 반쪽입니다 — 당겨서 새로고침되는 일이 더 흔합니다.
>
> **작업 중 발견한 함정** — 자기가 만든 주소 변경을 걸러낼 때 불린 플래그를
> 쓰면 안 됩니다. 해시 변경이 이벤트를 쏘지 않는 경우 플래그가 켜진 채 남아
> **다음번 진짜 뒤로가기를 통째로 삼킵니다.** 표식을 주소값 자체로 두고
> 그 값이 왔을 때만 무시하도록 고쳤습니다. 이 상황을 재현하는 테스트도 넣었습니다.
>
> 테스트 `router.test.mjs` 47건 + UI 레벨 29건. 이상한 주소 13종(`#/%%%`,
> `#/../../etc/passwd`, 5000자 주소 등)에도 화면이 비지 않는지 확인합니다.

### 1.2 화면이 꺼지고 다시 안 켜짐

WakeLock 코드는 있습니다(12군데). 문제는 **재획득이 없다**는 겁니다.

Screen Wake Lock은 탭이 백그라운드로 가면 브라우저가 자동으로 해제합니다.
그리고 돌아와도 **스스로 다시 걸리지 않습니다.** 다시 요청해야 합니다.
그런데 `visibilitychange` 리스너가 0개입니다.

실제 시나리오:

1. 추출 시작, 화면 켜짐 유지 작동
2. 1분 지점에 카톡 알림, 확인하러 나감
3. 돌아옴 → 타이머는 `Date.now()` 기반이라 멀쩡함 (이건 잘 만들어져 있습니다)
4. **그런데 화면 꺼짐 방지가 풀려 있음** → 30초 뒤 화면이 꺼짐
5. 다음 푸어 타이밍을 놓침

**고칠 방향**

```
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible' && session.running) reacquire();
});
```

한 줄짜리 수정인데 영향은 큽니다.

> **✓ 완료** — `WakeLock`에 `wanted` 플래그를 두어 "지금 잠금을 원하는 상태인가"를
> 기억하게 했습니다. 사용자가 직접 껐을 때(`release()`)는 `wanted`가 false가 되므로
> 돌아와도 다시 잡지 않습니다. 재획득 성공/실패는 `onChange`로 화면에 전달해
> 버튼이 실제 상태를 보여줍니다.
>
> 테스트 31건을 붙였습니다. 브라우저가 숨김 전환 시 잠금을 강제 해제하는 것까지
> 흉내 내는 스텁을 써서, 5회 왕복 후에도 잠금이 살아 있는지, 리스너가 누적되지
> 않는지, 거부됐다가 나중에 허용되면 복구되는지를 확인합니다.

### 1.3 저울을 보는 동안 폰을 못 봄

물리적인 문제입니다. 드리퍼에 물을 부으면서 폰 화면을 볼 수 없습니다.

소리와 진동이 있긴 합니다. 확인해야 할 것은 **예고가 있느냐**입니다.
"지금 부으세요"는 늦습니다. 3초 전에 알려줘야 주전자를 들 시간이 있습니다.

**고칠 방향**

단계 전환 3초 전 예비 신호(짧은 진동 1회) → 전환 시점 본 신호(길게 1회).
그리고 다음 목표 중량을 소리 없이도 알 수 있게, 화면 최상단에 큰 숫자 하나만
두는 "곁눈질 모드"를 두는 게 낫습니다. 지금은 정보가 여러 줄로 흩어져 있어서
한눈에 안 들어옵니다.

"예시"로 남기고 실제 사용은 직접 입력으로.

**둘째, 앵커 자동 보정.** 이게 진짜 가치입니다.

## 3. 오프라인과 로딩

현재 부팅 코드:

```js
const res = await fetch(path, { cache: 'no-cache' });
...
await Promise.all([ /* 8개 */ ]);
```

두 가지가 문제입니다.

**`cache: 'no-cache'`** — 앱을 열 때마다 200 KB를 다시 받습니다. 데이터는
거의 안 바뀌는데도요.

**`Promise.all`** — 8개 중 **하나만 실패해도 전체가 실패**합니다.
`renderError`로 안내 화면은 뜨지만, 사용자 입장에선 앱이 안 켜지는 겁니다.

부엌과 카페는 와이파이가 약한 곳이 많습니다. 지하 카페면 LTE도 약합니다.
그런데 이 앱은 **매번 네트워크가 필요합니다.**

### 고칠 방향

서비스워커를 넣고 데이터를 캐시 우선(cache-first)으로 바꿉니다. 앱 껍데기는
프리캐시하고, 데이터는 캐시에서 먼저 주고 뒤에서 갱신합니다(stale-while-revalidate).
두 번째 방문부터 **완전 오프라인으로 동작**합니다.

그리고 웹앱 매니페스트를 추가합니다. 이건 다음 항목과 직접 연결됩니다.

> **✓ 완료** — `sw.js`. 23개 파일(앱 셸 + 데이터 전부)을 설치 때 받아둡니다.
>
> `cache: 'no-cache'`를 두 군데서 제거했습니다. 서비스 워커가 캐시를 관리하는데
> 매번 서버에 되물으면 방해만 됩니다. **한 곳은 놓칠 뻔했습니다** —
> `loadDict()`에도 있었는데, 테스트를 먼저 써두어서 잡혔습니다.
>
> **`skipWaiting`을 자동으로 하지 않습니다.** 추출 3분 중에 앱이 갈아끼워지면
> 타이머가 날아갑니다. 새 버전은 대기 상태로 두고, 앱이 화면 아래 알림 바를
> 띄운 뒤 사용자가 누를 때만 교체합니다. **추출 중에는 그 알림조차 띄우지
> 않습니다** — 3분짜리 타이머 옆의 "새로고침" 버튼은 함정입니다.
>
> 테스트 `pwa.test.mjs` 35건. 핵심은 **프리캐시 목록과 실제 파일의 대조**입니다.
> 목록에 없는 파일이 하나라도 있으면 `cache.addAll`이 통째로 실패해 오프라인이
> 아예 동작하지 않는데, 브라우저 콘솔을 열기 전까지 아무 증상이 없습니다.
> 앱은 평소처럼 잘 돌아가니까요. 반대로 앱이 쓰는데 목록에 빠진 파일도
> 검사합니다.

## 4. 기록이 사라지는 것

로그가 `localStorage`에만 있습니다. 그런데 WebKit(사파리 / iOS의 모든 브라우저)은
**사이트와 상호작용하지 않은 채 7일이 지나면 localStorage를 포함한 모든
스크립트 기록 가능 저장소를 삭제합니다.** iOS 13.4 / Safari 13.1부터입니다.

즉 **2주쯤 커피를 안 내리면 그동안의 브루잉 로그가 통째로 사라집니다.**
학습 기록을 쌓는 게 이 앱의 목적인데, 그 기록이 제일 취약합니다.

여기서 중요한 사실이 있습니다. **홈 화면에 추가된 웹앱은 사파리와 별도로
취급되어 자체 사용일 카운터를 가집니다.** 매니페스트를 넣어 설치 가능하게
만드는 것이 단순한 편의 기능이 아니라 **데이터 보존 대책**인 셈입니다.

### 고칠 방향

세 겹으로 갑니다.

1. **매니페스트 + 홈 화면 설치 유도** — 7일 삭제 정책에서 벗어남
2. **IndexedDB로 이전** — localStorage보다 용량이 크고 구조적 (같은 7일 정책 대상이긴 하나 용량 한계가 사라짐)
3. **자동 내보내기 알림** — 로그 20건마다 "백업할까요?" 제안. 내보내기 기능은 이미 있습니다

> **✓ 1번 완료** — `manifest.webmanifest`. `display: standalone`, 아이콘 3종
> (192 · 512 · maskable), 바로가기 3개.
>
> 경로를 전부 상대(`./`)로 잡았습니다. `/`로 시작하면 도메인 루트를 가리켜
> GitHub Pages 하위 경로에서 깨집니다. 테스트가 이걸 검사합니다.
>
> 아이콘은 `tools/make-icons.ps1`로 생성합니다. PNG만 저장소에 넣어두면
> 나중에 색이나 모양을 바꿀 때 무엇으로 만들었는지 알 수 없습니다.
> 마크는 계기(타이머 링 + 중심점)입니다. 드리퍼 모양은 쓰지 않았습니다 —
> 한 번 시도했다가 작은 크기에서 구분이 안 돼 접었던 이력이 있습니다.
>
> 2번과 3번은 남아 있습니다. 다만 1번으로 가장 큰 구멍은 막혔습니다.

## 5. 공개 사이트로서의 문제

원래 목표가 "블로그 같은 공개 사이트"였습니다.

URL이 **하나뿐**이었습니다. 라우팅이 없으니 모든 화면이 같은 주소였습니다.

- 레시피 하나를 친구에게 링크로 보낼 수 없음 → **✓ 해결됨** (`#/brew/<id>`)
- 검색엔진에 "Hoffmann V60 레시피" 페이지가 잡히지 않음. 크롤러가 보는 건 스피너뿐
- 카톡·슬랙에 붙여도 미리보기 카드가 안 뜸 → **✓ 해결됨** (`og:image` 추가)

라우팅과 OG 태그로 첫 번째와 세 번째는 해결됐습니다. 검색엔진 노출까지
원하면 레시피 15건 정도는 정적 HTML로 미리 뽑아두는 게 현실적입니다.
빌드 스텝 없는 프로젝트 원칙과 부딪히지만, 노드 스크립트 하나로 끝나는 일이고
결과물이 정적 파일이라 원칙을 크게 해치지 않습니다.

## 6. 접근성

`aria-live`가 0개입니다.

`aria-pressed` 20개, `aria-label` 6개는 잘 쓰고 있습니다. 하지만 **시간에 따라
바뀌는 값이 스크린리더에 전달되지 않습니다.** 타이머, 단계 전환, 목표 중량 —
추출 가이드의 핵심 정보가 전부 조용합니다.

시각장애인 바리스타는 실제로 있고, 오히려 후각·미각 중심 작업이라 진입장벽이
낮은 분야입니다.

**고칠 방향** — 단계 전환 문구를 담는 `aria-live="assertive"` 영역 하나,
타이머는 `aria-live="off"`로 두고(초마다 읽으면 소음) 단계 경계에서만 알립니다.

## 부록 — 이미 잘 돼 있는 것

되돌아볼 때 헷갈리지 않도록 적어둡니다. 아래는 **손대지 않아도 됩니다.**

- **타이머가 절대시간 기반** (`Date.now()`). 백그라운드로 가도 안 밀립니다. 흔한 실수를 이미 피했습니다
- **이벤트 위임을 `init()`에서 한 번만 바인드.** 리스너 누적 버그를 겪고 고친 결과입니다
- **HTML 이스케이프가 300군데 이상 일관되게 적용됨**
- **로딩 실패 화면(`renderError`)이 `file://` 프로토콜 경우까지 구분해서 안내**
- **i18n 308키 전부 실제 번역됨** (동일한 값 3개는 "Special Coffee Wiki", `{c} / {t}`, "TDS %"로 번역이 불필요한 것들)
- **입력 범위 clamp 12군데**
- **저장 실패(QuotaExceeded) 처리 3군데**
